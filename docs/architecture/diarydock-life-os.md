# DiaryDock Life OS architecture

Status: implemented foundation and reviewed production system, 1 September 2026.

DiaryDock is a private household organisation application delivered through a Next.js 16 App Router web application and independently packaged iOS and Android applications, backed by Supabase Auth, PostgreSQL, Row Level Security and private Storage. The mobile applications run a signed local React/Capacitor bundle, maintain an encrypted offline database and use versioned HTTPS APIs; Android also provides an explicit native share-import bridge.

## System shape

- The browser and server use the signed-in person's Supabase session. Product records are owner-scoped by `auth.uid()` and shared reads are granted only through typed, active permissions.
- Supabase security-definer functions are the authority for compound mutations such as sharing, reminders, trusted access, Physical Links, Home Handover and analytics consent.
- Private files live in `diarydock-documents`. A document row can bind only to `<owner user id>/<document id>/<safe filename>`. Browser clients cannot upload or replace readable objects directly; the authenticated server verifies byte signatures and invokes the scanner boundary first.
- The Life Graph stores entities, relationships, provenance, facts, events, document links, inbox items, action requests/steps and append-only audit events. Cross-owner graph edges are rejected.
- The reminder engine turns authoritative dates into versioned, idempotent schedules. Guardian derives calm, dismissible findings from those schedules. It does not silently mutate source records.
- Search loads minimal candidates under the caller's RLS session. Ask DiaryDock selects no more than eight citations from that authorised set, sends only reduced records to the model, disables provider storage and has no action tools.
- Physical Links uses one shared strict contract across web and mobile. Reads are available from the encrypted mobile database, while every create, replace, rename, reassign, disable or revoke operation is online, revision checked and committed through a service-only transaction. Public tag secrets are generated by the server and returned once; the database stores only their verifier.
- Life Check uses the same deterministic organisation-score rules as the desktop product. The packaged app keeps a bounded encrypted snapshot for offline reading; answer changes are online, owner-derived, revision checked and patch only the Life Check sub-record without replacing unrelated account state.
- Home Handover uses one strict owner-free contract for web, phone and tablet. Its bounded private preview is readable from the encrypted mobile database; creating a draft or changing an explicit selection requires a recent sign-in, an online service-only transaction and the current draft revision. A separate explicit action can publish an immutable minimal copy to one confirmed recipient email for 30 days; it is revocable, excludes source IDs and files, and received copies remain online-only so revocation and expiry retain effect.
- First-time setup uses the same household choices, Life Check answers and dashboard-area catalogue on web, phone and tablet. The packaged flow is native and offline-readable from SQLCipher; final changes are bounded, owner-derived and revision checked, and one service-only transaction preserves all unrelated legacy state.
- Household ownership transfer uses the same web/mobile contract and requires a recent sign-in, an explicit 24-hour nomination and acceptance by the proposed Adult owner. One locked database transaction exchanges the authoritative owner and membership roles without moving or deleting household data.

## Product layers

1. Private records: app state, documents, reminders, assets and specialist household modules.
2. Organisation intelligence: Life Check, Organisation Score, Life Graph proposals, reminder rules and Guardian.
3. Deliberate access: household sharing, selected-member permissions, Physical Links and Trusted Emergency Access.
4. Guided workflows: intelligent capture, review inbox, Ask DiaryDock and private Home Handover drafts.
5. Governance: recent authentication, audit events, product-analytics consent, account deletion and truthful Vault boundaries.

## Deliberate limits

The current Vault is ordinary private server-managed storage, not end-to-end encrypted. Home Handover provides read-only in-app recipient access but does not send email, export files or publish a public link. Trusted Emergency Access has no automatic inactivity or legacy release. These limits are product and security gates, not implied capabilities.

Feature-specific decisions live in the companion documents in this folder and in `docs/security`.
